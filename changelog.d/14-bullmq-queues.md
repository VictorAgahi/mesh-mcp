- BullMQ / Bull queues named by an enum member resolve to the member's string value (9.0 T14, tag `enum_topic`). `@Processor(JobQueue.EMAIL)`, `@InjectQueue(JobQueue.EMAIL)`, `new Queue(JobQueue.EMAIL)`, `new Worker(JobQueue.EMAIL, ...)` and the `bull` / `bee-queue` constructors record the placeholder `${JobQueue.EMAIL:email}`, resolved against the workspace's string constants (enum members, `as const` keys, `static` fields) when the file is folded, through the config-topic machinery of T6. The producer and the consumer meet on `email-jobs`; two enums with one member name (`LegacyQueue.EMAIL`) are two queues, where both used to be the topic `email`. A member no indexed file declares keeps the member key, `exact`, as before. Redis streams, Kafka topics and event types given as enum members keep the member key: a codebase that names a stream and its event type alike links them by it.
- `analyze_impact` / `trace_flow` accept the member as written (`JobQueue.EMAIL`), its value or the recorded placeholder. A constant edit re-folds the unchanged files naming it (one extra pass after the reload, never a loop); an incremental state equals a cold rebuild.
- Bounded and counted: at most 4,000 string constants per file (`IndexHealth::files_const_capped`, `doctor` warns), topic-shaped values only, member paths only (a bare `const TOPIC` never answers a `process.env.TOPIC` placeholder), 2 MB stack probe with a 3,000-member enum and an alias cycle. `BullModule.registerQueue` is not a producer. See `docs/parser-support.md` section 3.7.
- Parse cache `SCHEMA_VERSION` 19 -> 20: a TypeScript / JavaScript record can now hold an enum-member queue placeholder and `FileIndex::const_capped`; existing caches are re-parsed once. New golden corpus `examples/eda/bullmq-enum-queues` and `tests/golden/events/bullmq-enum-queues.expected.yaml`, new tag `enum_topic`.
