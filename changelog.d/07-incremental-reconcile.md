### Changed

- Incremental reload: the contract graph's edges are now reconciled incrementally (`ContractGraph::reconcile_delta`). Only the edges the changed files can reach are recomputed: importers whose targets look up a changed name, package or `package/name` key; topics whose producers, consumers, matching wildcard subjects or event-bus node changed; handlers that are new or whose resolved `Service.Method` changed; callers that are new, renamed, inherit through a changed field binding, or call a changed gRPC service. A change to more than 20% of the nodes, a `.proto` method change (for the gRPC families), interleaved call records (for `CallsRpc`), an alias config edit and a graph without a change journal still take the full rebuild. The full `reconcile_edges` is unchanged (same fingerprint and same JSON graph, edge order included, as before on four corpora) and remains the oracle: tests check that the delta ends in the same graph, edge order and resolved handler names included, after every step of seeded random edit sequences.
- Measured on a 30,000-file synthetic workspace (`gen_synthetic.py --contracts`, 109k nodes), one file edited per reload, release build, load average 8 to 19: reconcile went from a median of 182 ms (63% of the reload) to 2.4 ms (2%), and the whole in-process reload from a median of 283 ms to 105 ms. The rest of a reload is now mostly the snapshot clone (about 70 ms).
- Reload phase timings are logged at debug level on `mesh::watcher`.
