- Calls layer on Java (Spring), Go and Python (9.0 T2b), same model as TypeScript: `Callable` nodes and `Calls` edges from an entry to a producer, resolved without a type checker.
  - Java: constructor-injected, `@Autowired` and Lombok-style final fields are read as typed fields; types resolve through a qualified import, a wildcard import or the package (the directory); `this.m()` and unqualified `m()`; an interface with one implementation is `exact`, several `ambiguous`.
  - Go: struct fields (the dependency a `NewX(dep Dep)` constructor stores), method receivers (`s.dep.M()`, `s.M()`), functions of the same package (any file of the directory), package-qualified calls resolved through the directory an import path's tail names; interfaces match struct types by method set (several: `ambiguous`; more than 64: dropped and counted). A client built in `NewT` (a `kafka.Writer` literal) makes the methods of `T` that call through a field the entry or producer callables.
  - Python: annotated `__init__` parameters (`self._dep = dep`), annotated class attributes, `self.m()`, `self.dep.m()`, imported and same-module functions, `mod.f()` on an imported module, relative and absolute imports, package `__init__` re-exports. A parameter without an annotation gives no edge: no name-based guess.
  - Test files, generated files (`*.pb.*`, `zz_generated*`, ...) carry no call facts; the number of Java, Go and Python files skipped for that reason is counted (`IndexHealth::files_call_facts_skipped_path`, listed by `doctor`).
  - A parameter or local named like an imported module, package or function (`orders.save()` with a parameter `orders`) is not a call on that module: Python and Go check parameters, assignments, loop and `with` targets (Java already did). Residual limit: a name bound after the call, or in a nested function, is judged for the whole enclosing callable.
  - An identifier receiver guessed to be a field of a base class (Java, no `this.`) gives a `heuristic` edge (`inherited_field`), never `exact`. The `abstract` modifier is read as a keyword, not as a word of an annotation argument.
- Memory: the call sites of Java, Go and Python files that lie on no entry -> producer path are dropped after the derive (callables, imports, injections and types stay); a later edit that brings such a file onto a path makes the indexer re-extract it in one restoring pass (`Calls refresh`). The previous derived layer is freed before the next one is built, and the pair list of a derive is a sorted vector instead of a map.
- Parse cache `SCHEMA_VERSION` 13 -> 15 (14 was never released): existing caches are re-parsed once.
- New counters in `IndexHealth`, listed by `doctor` (warning, a call path may be cut): `call_interfaces_overflow` (Go interfaces left without implementations past the 64-implementation cap), `call_hops_capped` (base-class, embedding and re-export lookups cut at 16 hops), `call_interfaces_unmatched` (Go interfaces not matched past 1,000,000 interface x struct pairs per repository), `call_files_missing_sites` (candidate files whose call sites could not be restored).
- Go: the per-file set of methods that call through a field is computed once, and the methods a constructor makes entries or producers are memoized per constructor (a constructor with thousands of methods and many producer sites was quadratic).
- A scan pass writes its parse-cache records per chunk of 2,048 files instead of holding every record of the workspace until the pass ends: the peak of a cold build on kubernetes drops by about 70 MB (this also repays the call facts the Go, Java and Python extractors add).
