- Add SQL producers and consumers (9.0 T5, tag `sql`): `INSERT INTO <outbox table> (topic, ...) VALUES ('literal', ...)` (table named `*outbox*` or `event_queue`; key from the first column named `topic`, `topic_name`, `channel`, `event_type`, `event_name` or `routing_key`), `NOTIFY ch`, `pg_notify('ch', ...)` and `LISTEN ch`, read from `.sql` files (function and trigger bodies after `AS` or `DO` are read as code; any other `$$` text is a string) and from the SQL string literals of TypeScript / JavaScript, Go, Java and Python files. They are registered as `EventStream` nodes through the ordinary producer / consumer path, so `topic_producers`, `analyze_impact` and `trace_flow` see them unchanged. A key that is not a static literal (bind parameter, concatenation, column) is not resolved: no producer is registered and no key is made up. Comments and string literals that merely mention `INSERT` are ignored; in a host-language literal `NOTIFY` / `LISTEN` must be upper case with a channel that starts with a letter or `_` (`log.info("Notify admins")` is a log line), and host escapes (`\'`, `\n`) are decoded.
- The scanner is a bounded lexer (no new dependency, no regex). A `.sql` file has its own guard: the 384 KB budget and the null-byte sniff only, no line-length or nesting rule (a long comment line or a `-- (` banner no longer drops the file). `.sql` is a watched extension in any case.
- Caps are counted, never silent: `IndexHealth::files_sql_capped` (files cut by 4,096 sites, 512 `VALUES` rows, 4,096 scanned literals or 200,000 tokens; `doctor` warns) and `IndexHealth::sql_sites_unresolved` (outbox inserts and `pg_notify` calls with a non-literal key, listed by `doctor`).
- Parse cache `SCHEMA_VERSION` 16 -> 17 (T5 bumps to 17 on top of T7's 16, so a 15 cache goes 15 -> 16 -> 17 in the release): the record gains `FileIndex::sql_unresolved` / `sql_capped`, and `.sql` files and the SQL strings of TS/JS, Go, Java and Python files now carry events; existing caches are re-parsed once (the version is part of every cache key, older rows are never read and age out under the cache quota).
- SQL sites carry no broker (`producer_brokers` / `consumer_brokers` stay empty): an outbox insert's key is usually the topic its relay publishes, so a SQL site joins the channel of every broker that uses the name, `heuristic` when two or more known brokers use it, exactly like any other site of unknown broker (T7 rule); `Broker` is unchanged.
- New golden corpus `examples/eda/sql-outbox` and `tests/golden/events/sql-outbox.expected.yaml` (12 producers, 4 consumers, 12 negatives); the 7 existing corpora score byte-identically before and after.
