- Add SQL producers and consumers (9.0 T5, tag `sql`): `INSERT INTO <outbox table> (topic, ...) VALUES ('literal', ...)` (table named `*outbox*` or `event_queue`; key from the first column named `topic`, `topic_name`, `channel`, `event_type`, `event_name` or `routing_key`), `NOTIFY ch`, `pg_notify('ch', ...)` and `LISTEN ch`, read from `.sql` files (trigger and function bodies included) and from the SQL string literals of TypeScript / JavaScript, Go, Java and Python files. They are registered as `EventStream` nodes through the ordinary producer / consumer path, so `topic_producers`, `analyze_impact` and `trace_flow` see them unchanged. A key that is not a static literal (bind parameter, concatenation, column) is not resolved: no producer is registered and no key is made up. Comments and string literals that merely mention `INSERT` are ignored.
- The scanner is a bounded lexer (no new dependency, no regex): `.sql` files go through the full lexical guard (384 KB, null-byte sniff, 1,024-byte lines, nesting 64), at most 4,096 sites per file; `.sql` is a watched extension.
- Parse cache `SCHEMA_VERSION` 15 -> 16: existing caches are re-parsed once.
- New golden corpus `examples/eda/sql-outbox` and `tests/golden/events/sql-outbox.expected.yaml` (8 producers, 3 consumers, 8 negatives); the 7 existing corpora score byte-identically before and after.
