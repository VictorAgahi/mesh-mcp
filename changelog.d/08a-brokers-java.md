- Java message brokers beyond Kafka (9.0 T8a, tag `jvm_broker`): RabbitMQ (`@RabbitListener` queues, `queuesToDeclare`, `@QueueBinding` routing keys, class-level listeners with `@RabbitHandler`; `RabbitTemplate` / `AmqpTemplate` `convertAndSend` and `send`), JMS (`@JmsListener`, `JmsTemplate` / `JmsMessagingTemplate`, `new ActiveMQQueue("x")`), SQS and SNS (`@SqsListener`, `SqsTemplate`, `QueueMessagingTemplate`, `SnsTemplate`, `NotificationMessagingTemplate`, `SqsClient.sendMessage` / `receiveMessage`, `SnsClient.publish` with a `queueUrl` / `topicArn` literal, inline or in a local request), Redis pub/sub (`convertAndSend`, `addMessageListener` with `ChannelTopic` / `PatternTopic`, also through a bean topic), NATS (`publish`, `request`, `subscribe`, `createDispatcher(...).subscribe`) and Google Pub/Sub (`PubSubTemplate.publish`). Each site is recorded under its own broker, so a queue named like a Kafka topic is a different channel. See `docs/parser-support.md` 3.7.
- New broker key `jms` (slug `jms`, `Broker::Jms`, declared last so no existing hub order moves): the JMS API hides its provider, so it is one channel space of its own. `kafka:` / `rabbitmq:` / ... hubs and the golden slug lists are unchanged apart from this entry.
- A name is read only when a call site shows it: a string literal, a `final` string field of the same file, a destination object (`new ChannelTopic("x")`) or an `@Value("${a.b}")` placeholder resolved against the configuration like a `@KafkaListener` topic. A call counts only on a receiver declared with the client class in a file that imports the library; a `convertAndSend` of an unrelated class, a log line and a variable name are never sites. Kotlin is not extended.
- Bounds: at most 2,000 JVM broker sites per file (`MAX_JVM_BROKER_SITES_PER_FILE`), counted in `IndexHealth::files_jvm_brokers_capped` and listed by `mesh-mcp doctor` (a warning); iterative walk, a 256-node search per argument. Golden: `tests/golden/events/jvm-brokers.expected.yaml` (new corpus `examples/eda/jvm-brokers`); the 9 earlier golden corpora are byte-identical on `scripts/golden/score_events.py --chain-tool trace_flow` and on `scripts/golden/compare_tools.py` (222 answers).
- Parse cache `SCHEMA_VERSION` 19 -> 20 (whoever merges after T14 rebases and bumps again): the record of a Java file can now hold JVM broker sites; existing caches are re-parsed once.
