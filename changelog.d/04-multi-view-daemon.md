### Breaking
- Daemon socket naming: inside a Git repository `meshd` is now named by the repository, not by the directory and config file. The socket is `meshd-<family_id>.sock` (named pipe `mesh-mcp-<user>-<family_id>` on Windows), where `family_id` hashes the canonical common Git directory and the binary version, so every worktree and every config file of one repository share one daemon. The spawn lock (`meshd-<family_id>.lock`), the daemon meta file (`~/.cache/mesh-mcp/meshd/<family_id>.meta`) and the auto-spawn log (`meshd-<family_id>.log`) are keyed the same way. Outside Git nothing changes: the per-directory, per-config `workspace_id` still names the daemon, so two config files in one plain directory still get two daemons. `MESH_SOCKET_PATH` still overrides the socket path.
- Mandatory hello: every connection to `meshd` must start with one line, `{"meshd_hello":1,"worktree":"<canonical dir>","config":"<canonical config>"|null}`, read under 8 KiB and a 5 s timeout. The daemon answers `{"meshd_hello_ok":1}` or `{"meshd_hello_error":"<reason>"}`; a connection whose first line is anything else (a raw JSON-RPC frame included) gets the error line and is closed. `mesh-mcp run` sends the hello before forwarding any client byte and falls back to standalone mode, with a warning on stderr, when the daemon refuses it. A `mesh-mcp` older than 8.0.0 cannot talk to this `meshd` and vice versa; the version is already part of the socket name, so they never meet.

### Changed
- One `meshd` per repository serves one view per worktree and config file: N worktrees of a repository give one daemon process. Each view has its own graph, file watcher and config follower (RAM still holds one graph per active view); all views share one watcher pool, one config-reload pool, one audit logger and the repository's parse cache. A view is built on its first hello (once, however many sessions ask at the same instant) and answers `tools/call` with "still indexing" until its first snapshot while `initialize` and `ping` work. Without a config file, each session directory is its own view.
- A hello is refused when its directory (or the directory of its config file) is not in the daemon's repository, when outside Git it does not name exactly the directory and config the daemon was started for, when its config cannot be loaded, or when the workspace-root guard refuses it. A session only ever receives answers from the view its own hello named.
- Idle lifecycle: a view with no session for `--idle-timeout-minutes` (default 30) is dropped (watcher and config poller cancelled, state freed) and rebuilt on the next hello; the daemon exits once it has no view and no client left. The startup-grace orphan guard is unchanged.
- `mesh-mcp doctor` reports the views the running daemon serves (count, worktree, config file, sessions, views built since start), read from the meta file the daemon rewrites whenever a view is built or dropped. The per-view config status record stays keyed by the directory's own `workspace_id`.
