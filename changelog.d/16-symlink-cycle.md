- A symlink to an ancestor directory inside a root (`src/loop -> ..`) no longer crashes `run --standalone` at startup with a stack overflow (9.0 T16). The crawler followed every in-root directory symlink with a recursive sub-crawl that restarted its visited set and its depth limit on each call. The walk is now iterative with one visited set (every directory walked, real or reached by a link) and one depth budget for the whole crawl: a link to an ancestor, itself, a sibling or around a cycle is not re-entered, a link opens a walk with the budget left at its depth, and at most 1024 link targets are walked per root (a crafted tree of tens of thousands of links no longer costs a walk each).
- Every directory symlink not followed (target already walked, outside the root, out of depth budget, over the cap) is counted in `IndexHealth::dir_symlinks_not_followed` and shown by `doctor` as "N directory symlink(s) not followed". Files inside the root are still indexed once, under their real path; a target outside the root is still never read. New `FilesystemCrawler::crawl_scope_report` returns the files with the count; `crawl_scope_with` is unchanged for its callers.
- Known limits: a dangling or self-referential link (`x -> x`, ELOOP) is not a directory and is not counted. A link target already walked is counted although no file is lost.
- No `SCHEMA_VERSION` bump: extraction output is unchanged. No config change.
