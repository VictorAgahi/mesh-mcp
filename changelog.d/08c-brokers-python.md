- Python message brokers beyond Kafka and Celery (9.0 T8c, tag `py_broker`): RabbitMQ (pika `basic_publish` / `basic_consume` / `basic_get`, aio-pika `exchange.publish` / `queue.consume` / `queue.iterator`, kombu `Producer.publish` / `Consumer(queues=...)`), Redis pub/sub (`publish`, `subscribe`, `psubscribe`), NATS (`publish`, `request`, `subscribe`, JetStream), SQS / SNS (boto3 `send_message`, `receive_message`, `publish` with `QueueUrl` / `TopicArn`) and Google Pub/Sub (`publisher.publish`, `subscriber.subscribe`). Each site is recorded under its own broker, so a queue named like a Kafka topic is a different channel. See `docs/parser-support.md` 3.10.
- A call counts only on a receiver built from the library (a call on an imported module or class, a `with` target, a `self.x` assigned in its class, an annotated parameter) in a file whose parsed `import` statements bring it in; Python scopes apply (parameters, loop, `except`, comprehension and lambda variables, a local class of the same name hide a client; a name bound to two things is ambiguous). A name is read only when the call shows it (a string literal, a constant of the same scope chain, a keyword literal, an `os.environ` / `os.getenv` read as a `${KEY}` placeholder); a default of `os.getenv("K", "d")` is never a name; a producer never takes a wildcard key; a credential-shaped literal is not a name.
- The shape-based Kafka reader keeps its behaviour for an unbound receiver; a call on a client the file shows to be Kafka now carries the `kafka` broker, a call on another broker's client is no longer read as Kafka, a call on an instance of a class the file declares is nobody's producer, and the gaps `KafkaConsumer("a", "b")` and `subscribe(topics=[...])` are filled.
- Bounds: at most 2,000 Python broker sites per file (`MAX_PY_BROKER_SITES_PER_FILE`), counted in `IndexHealth::files_py_brokers_capped` and listed by `mesh-mcp doctor` (a warning); iterative walk, bounded receiver and dotted-path chains, 32,768 scope bindings. Golden: `tests/golden/events/py-brokers.expected.yaml` (new corpus `examples/eda/py-brokers`); the 11 earlier golden corpora are byte-identical on `scripts/golden/score_events.py --chain-tool trace_flow` and on `scripts/golden/compare_tools.py` (296 answers).
- Parse cache `SCHEMA_VERSION` 22 -> 23 (T8b, Go, also bumps to 23: whoever merges second rebases and bumps again): the record of a Python file can now hold broker sites and a broker tag on its Kafka sites; existing caches are re-parsed once.
