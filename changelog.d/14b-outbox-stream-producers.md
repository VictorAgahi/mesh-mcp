- Declared producer helpers (9.0 T14b): `[[engines.contracts.producer_calls]]` names a helper of the project (an outbox entity, a stream publisher) and its calls become producers in TypeScript and JavaScript, tag `declared_call`. `callee` is `method` or `Receiver.method`; `topic_keys` lists the keys of the call's object literal read as topics (a job or event type, `targetServices: [Streams.A, Streams.B]`), `queue_keys` the keys read as BullMQ queues (an enum member resolves to its value, the same member name in two enums stays two queues), and with no keys argument `arg` is the topic. `JobsOutboxEntity.createJob({ type: JobType.SCAN_FILE, target: Queue.STORAGE })` is a producer of `scan_file` and of the queue `storage-queue`, each on its own line.
- Every declared producer is `heuristic` (the helper is a name the operator vouches for; there is no `exact`), has no broker, and never joins across brokers. The call is read in the syntax tree (not a comment or a string); a `Receiver.method` callee needs that receiver, a local of the same name hides the helper, an import alias of the class is not followed. A value that is not a static name (a parameter, `TABLE[kind]`) or is refused as secret-shaped is counted in `IndexHealth::declared_call_sites_unread` and printed by `doctor`, never guessed; 2,000 sites per file and 64 entries, counted (`files_declared_capped`, `doctor`).
- On the Volontariapp workspace the unresolved share ("no producer statically resolved") goes from 82/136 = 60.3% to 74/156 = 47.4% with the helpers declared; the 30.1% target is NOT met (see docs/parser-support.md section 3.11 and the PR for what remains and why).
- Parse cache `SCHEMA_VERSION` 25 -> 26 (declared producer sites, `FileIndex::declared_unread` / `declared_capped`); the declaration is part of the config fingerprint and a change to it is a full reload. New golden corpus `examples/eda/declared-producers`, new tag `declared_call`, `doctor` check "Producer calls". Not read: lookup tables (`type: TABLE[kind]`), generic type arguments, `new` expressions, an alias of the receiver class, other languages.
