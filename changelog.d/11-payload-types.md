- Payload types per topic and the publisher-versus-consumer check (9.0 T11), the events analogue of the `.proto` wire check: `event_anomalies` gains a `payload_mismatch` class. Per topic hub (per broker: two brokers sharing a name are never compared) with live producers and consumers, it reports the non-optional fields a consumer's declared type expects that no producer sends, the fields published that no consumer's type declares, primitive field type differences (`string`, `number`, `boolean`, arrays of them) and whether the type names differ, with `path:line` of each type declaration, field and site. Tool count unchanged (nine).
- Surface: a class of `event_anomalies`, not a section of `analyze_impact` or `diff_mesh`: the check is a set of rows over the whole workspace, per broker-qualified hub, which is exactly the population and the scope / paging / redaction machinery of the anomaly report (the check runs inside its pass, over the hubs it already partitions). `analyze_impact` answers for one target, and `diff_mesh` compares two versions of the code, not two ends of a channel; T10 did not extract payload fields (its "not compared" line now points to this class).
- Extraction (`mesh-parsers` `languages/payload.rs`, `mesh_core::PayloadFacts`, parse cache `SCHEMA_VERSION` 25 -> 26): TypeScript / JavaScript interfaces, object type aliases and classes, Java classes and records (fields: name, declared type, line, optional); the payload type of NestJS handlers (`@Payload()` or first parameter), BullMQ `Job<T>` / `Queue<T>` / `Worker<T>` / `@InjectQueue` `Queue<T>`, `emit` / `send` / `add` payload arguments (`new T()`, `x as T`, object literals, typed parameters and locals), Spring listeners (`@Payload`, `ConsumerRecord<K, V>`, `Message<T>`), `send` / `convertAndSend` payload arguments and the `V` of a `KafkaTemplate<K, V>` receiver. Names, declared types and lines only: a literal's value is never read (its JSON family is).
- Never a false "no mismatch": an untyped payload (a raw string, `any`, `JSON.stringify(...)`), an undeclared or ambiguous type name, more than 8 payloads on one side (`MAX_PAYLOAD_SHAPES_PER_TOPIC`), a field list past 64 fields (`MAX_PAYLOAD_FIELDS_PER_TYPE`) or with an `extends` / spread are counted and said "not compared" (per direction or per topic, the topics named in the footer); per-file caps (512 sites, 256 types) are counted. Credential-shaped field and type names print as `[REDACTED_SECRET: USE_ENV_OR_LOCAL_FALLBACK]`.
- Tests: hand-annotated truth `tests/golden/events/payloads.report.yaml` over the new fixture `examples/eda/payload-types` (NestJS, BullMQ, Spring Kafka and RabbitMQ; three mismatches, five matching decoys including one name on two brokers, two not-compared topics), consumed by `crates/mesh-server/tests/payload_types.rs` (exact rows, scope, class filter, byte-identical over runs and a cold and warm cache, caps, ambiguity, runtime-built credential canaries absent from the answer and the cache); extractor unit tests in `languages/payload.rs`. Not a `<corpus>.expected.yaml`: the event scorer totals are unchanged.
- Known limits: other languages (Go, Python, Kotlin, C#) are not read; a consumer's expected fields are its declared type's, not the fields its code accesses; field names are compared as written (no serializer naming strategy); a named object field type is not compared; Spring Cloud Stream functional beans (`Consumer<T>`) are not read; a node holding two payload sites of different types for one topic is ambiguous.
- Review round 1 (same PR): an imported payload type name (`import { Refund as Order }`, a default import, a path alias) resolves only through its import, never to a same-named type of another file; an import from a package or a file that is not indexed is not compared. Every TypeScript type alias is declared (an intersection, union or utility alias without fields, not compared) so it shadows a same-named class; a declaration past the 256-type cap keeps its name. Quoted keys are bare field names. A gap list taken from a partial field list says so. Two payloads of one node for one topic are ambiguous (tested). Type names pass the credential gate too (`member_consts::identifier_is_credential_named`, camel-case aware). A row too long is clamped in its findings, never in its "not compared" notes. Incremental reloads (edit, delete) update the payload rows (tested). New fixture `examples/eda/payload-imports`.
- Review round 2 (same PR): the literal topic argument a payload site keeps (to tell two sites of one node apart) has every `${key:default}` default stripped at extraction and is dropped when it still is not a printable name, so a placeholder default (possibly a credential) never reaches the file index or the parse cache through a payload fact (it did: `@RabbitListener` / `@JmsListener` / `@SqsListener` defaults, caught by the T8a canary test). Regression test with runtime-built canaries on TypeScript and Java (file index, payload facts, cache database and its -wal / -shm).
