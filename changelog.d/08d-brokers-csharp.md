- C# message brokers beyond Confluent.Kafka (9.0 T8d, tag `cs_broker`): MassTransit (`IConsumer<T>` / `IJobConsumer<T>` classes, `Publish` / `Send` on `IPublishEndpoint`, `ISendEndpoint`, `IBus`, `IBusControl`, `ConsumeContext`, `ReceiveEndpoint("queue")` inside `UsingRabbitMq` / `UsingAzureServiceBus` / `UsingAmazonSqs` / `UsingInMemory`, `GetSendEndpoint(new Uri("queue:name"))`), NServiceBus (`IHandleMessages<T>` / `IAmStartedByMessages<T>` classes, `Publish` / `Send` / `SendLocal` / `Reply`) and the Azure Service Bus SDK (`ServiceBusClient.CreateSender` / `CreateProcessor` / `CreateSessionProcessor` / `CreateReceiver`, `[ServiceBusTrigger]`, `[ServiceBusOutput]`, `[ServiceBus]`). See `docs/parser-support.md` 3.12.
- A call counts only on a client the file shows: a parsed `using` of the library's namespace (or the fully qualified name), no type or `using` alias of the file named like the client (a local `interface IConsumer<T>` or `class ServiceBusClient` hides the library's), and a receiver of the declared client type (field, property, parameter, local, `this.x`, `new T()`). `IConsumer<TKey, TValue>` (Confluent.Kafka) is never MassTransit's, `IHandleMessages<T>` of Rebus is never NServiceBus's. A message type is a generic argument, a `new T(...)` or a variable of declared type `T` (never a type parameter, `object` or a generic type); a queue is a string literal, a `const` / `static readonly string` of the file, an `Environment.GetEnvironmentVariable` or `IConfiguration` read (the placeholders `${K}` / `${A__B}`, resolved like section 3.6) or a Functions `%Setting%`; a default (`?? "d"`, `GetValue<string>("k", "d")`) is never a name; a connection string, a credential-shaped literal or constant, a credential-named configuration key and a wildcard are not names and register nothing.
- The bus (`rabbitmq`, `servicebus`, `sqs`, `inproc`) is known only where the same file names it (`UsingRabbitMq`, `UsingAzureServiceBus`, `UsingAmazonSqs`, `UsingInMemory`, `UseTransport<RabbitMQTransport>()`, `new AzureServiceBusTransport(...)`); a consumer class of another file has no broker, joins the channel of its name on every broker (`heuristic`) and is never tagged `kafka`. The Azure Service Bus SDK and Functions attributes are `servicebus`. Brokers never join; `diff_mesh` names the broker of a removed C# site that is not Kafka.
- Secrets: a signature line holding a secret-shaped literal (`Connection = "Endpoint=sb://...;SharedAccessKey=..."` on an attribute line) is stored masked in files that name one of the libraries, and `smart_search` shows a connection-string literal of any snippet masked (`mesh_core::config_values::mask_connection_strings`, a literal holding a `SharedAccessKey=`, `AccountKey=`, `AccessKey=`, `Password=`, `Pwd=` ... pair).
- Bounds: at most 2,000 C# broker sites per file (`MAX_CS_BROKER_SITES_PER_FILE`), counted in `IndexHealth::files_cs_brokers_capped` and listed by `mesh-mcp doctor` ("broker sites (Java, Go, Python, C#)", a warning); iterative walks, 16,384 declared names. Golden: `tests/golden/events/cs-brokers.expected.yaml` (new corpus `examples/eda/cs-brokers`, 31 sites, 2 chains, 11 negatives).
- Not read, documented in 3.12: `RabbitMQ.Client`, Rebus, Wolverine, `Microsoft.Azure.ServiceBus`, Event Hubs, request clients, `RouteToEndpoint`, `ConfigureEndpoints`, a `global using` of another file, a send through the variable that holds a `GetSendEndpoint` result. The generic Confluent.Kafka reader (`Produce("lit")` / `Subscribe("lit")` on any receiver) is unchanged.
- Parse cache `SCHEMA_VERSION` 27 -> 28: the record of a C# file can now hold broker sites and masked signatures; existing caches are re-parsed once.
