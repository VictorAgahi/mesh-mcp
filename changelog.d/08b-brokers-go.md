- Go message brokers beyond Kafka (9.0 T8b, tag `go_broker`): RabbitMQ (`amqp091-go`, `streadway/amqp`: `Channel.Publish[WithContext]` on the routing key or the fanout exchange, `Consume` / `Get` on the queue or the routing keys of a `QueueBind` of the same file, `q.Name` of a declared queue), NATS (`nats.go` `Publish`, `PublishMsg`, `Request`, `Subscribe`, `QueueSubscribe`, `ChanSubscribe`, `SubscribeSync`, both JetStream APIs), Redis (`go-redis` v6 to v9 `Publish`, `Subscribe`, `PSubscribe`), SQS and SNS (`aws-sdk-go` v1 and v2 `SendMessage`, `ReceiveMessage`, `Publish` with the `QueueUrl` / `TopicArn` of the request literal, `GetQueueUrl` results) and Google Pub/Sub (`Topic("t").Publish`, `Receive` of a subscription created on a topic of the file). Each site is recorded under its own broker, so a queue named like a Kafka topic is a different channel. Kafka gains the two variants the Go extractor did not read: sarama `ConsumerGroup.Consume` and franz-go (`kgo.Record`, `ConsumeTopics`, `DefaultProduceTopic`). See `docs/parser-support.md` 3.9.
- A call is read only when its receiver is declared with the library's client type (a parameter, a struct field through its receiver, a constructor or accessor result, a function result of the file) in a file with a parsed import of the library; a local type of the same name, a package name hidden by a variable and a commented-out import are not clients. A name is a literal, a constant or variable of the file that nothing assigns again, or an `os.Getenv` / `viper` read (the `${KEY}` placeholder of T6); a default a variable falls back to is never a name, and a producer never takes a wildcard key.
- A `Subscribe("x")` of a NATS or Redis client (or of a method a type of the file declares) is no longer read as a Kafka consumer by the older Go heuristics, in the files that import one of these libraries.
- Migration: the parse cache record schema goes from 22 to 23 (`FileIndex::go_brokers_capped`; the version is part of every cache key, so version 22 rows are never read and the first scan after the upgrade re-extracts every Go file once).
- Bounds: at most 2,000 Go broker sites per file (`MAX_GO_BROKER_SITES_PER_FILE`), counted in `IndexHealth::files_go_brokers_capped` and listed by `mesh-mcp doctor` (a warning); iterative walks, resolution depth 8. Golden: `tests/golden/events/go-brokers.expected.yaml` (new corpus `examples/eda/go-brokers`); the 11 earlier golden corpora score the same on `scripts/golden/score_events.py --chain-tool trace_flow` (229 / 2 / 13, chains 31 of 35).
