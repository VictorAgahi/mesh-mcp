- AsyncAPI 3 export of the observed event graph and the declared-versus-code diff (9.0 T12): a new tool `export_asyncapi` (tools nine -> ten). `mode: export` renders the observed graph as one valid AsyncAPI 3.0 document in a fenced YAML (or JSON) block: a channel per topic hub (per broker, address = the engine's normalized key), a `send` operation per producer site and a `receive` operation per consumer site with `path:line` and a confidence (`exact` / `heuristic` / `ambiguous`), the payload schema when the T11 payload check knows the type (the same data, not re-extracted), a server per known broker (host `unresolved.invalid`, never guessed; an unknown broker is `heuristic` and gets no server). A `${KEY}` placeholder topic is not a channel: it is counted and listed under `x-mesh.not_statically_resolved`. `mode: diff` compares the declared AsyncAPI 2.x / 3.x document(s) the index found (read from disk at call time) with the code: declared but not in code, in code but not declared (channels and directions), payload disagreements, broker disagreements, with the engine's keys (`normalize_topic_key`, `{param}` and wildcard subjects through `subject_matches`, broker qualifiers).
- Surface (decided with evidence, as asked): a new tool, not a class of `event_anomalies` or a section of `analyze_impact` / `diff_mesh`. The answer is a document with its own paging rule (a page is a valid standalone document of fewer channels and says `PARTIAL DOCUMENT`, how many channels are not in it and the next `offset`, never a cut document), its `diff` mode reads a source no other tool reads (declared files, through the path jail, no symlink, schema size budget, 20 per call), and `event_anomalies` / `analyze_impact` answer with rows over the graph or for one target. Every count claim is fixed (README, SETUP, CLAUDE.md, `docs/mcp-tools.md`, `docs/governance-rsah.md`, `docs/architecture/*`, server instructions, `mesh-mcp init` routing text) and pinned by a test.
- No extraction change, no `SCHEMA_VERSION` bump (27): `mesh_core::ContractGraph::observed_events` / `site_payloads` / `declared_asyncapi_files` (`contracts/asyncapi.rs`, `contracts/payload.rs`) read the graph; `mesh-parsers` `asyncapi/` holds the document builder, the declared reader and the diff. The channel nodes a declared AsyncAPI file contributes are left out of the observed side (they are the declaration). The `coverage_notes` of `event_anomalies` moved to a shared helper (same text).
- Bounds: at most 28 KB of document per page (a page holds at most `limit` channels, default 20, and fewer when the budget says so, never fewer than one), 40 operations per direction per channel (the rest counted in `x-mesh-operations-not-listed`), 20 declared documents and 2,000 declared channels per document, local `$ref`s up to 8 hops (an external or dangling `$ref` is counted, its payload not compared). Topic and type names pass the shared name gates before they are printed (a credential-shaped topic is counted as unresolved without its name, a credential-shaped type is `type name redacted`, a credential-shaped field is left out and counted); declared rows go through the same gates.
- Tests: hand-annotated truth `tests/golden/events/asyncapi.report.yaml` over the new fixture `examples/eda/asyncapi-declared` (NestJS, BullMQ, Spring Kafka, a version 3 and a version 2 declared document that deliberately disagree: one declared channel not in code, three code channels or directions not declared, two payload disagreements, one broker disagreement, decoys for a matching channel, a wildcard-heard channel and a redis-admitted queue), consumed by `crates/mesh-server/tests/asyncapi_export.rs` (structural validation of the exported document: required keys, every `$ref` resolves, operations name existing channels and only messages of their channel, unique ids; determinism over runs, a re-index and JSON versus YAML; paging; scope and jail; credential canaries built at runtime; caps; a symlinked declared file; the tool counts in the docs) and unit tests in `asyncapi/{declared,diff,export}.rs`.
- Known limits: no `bindings`, no real `host`; the channel address is the engine's lower-case key; only TypeScript / JavaScript and Java payloads are typed; an external `$ref` of a declared document is not followed; a version 3 declared channel is still indexed under its id, not its `address` (pre-existing, 3.2), so its id also appears as a topic in `event_anomalies`.
- Fix round 1 (same PR): an observed channel is never reported `undeclared` while a declared source is incomplete (a document cut at the 2,000-channel cap, a v3 channel with no `address`, a file past the 20 per call, unreadable / unsupported / symlinked, or rejected by the indexer): it goes to a new `Not compared` class with the reasons, and the headers say when the list is complete. A declared payload is compared only with the message named like the code type (no more single-message fallback); otherwise an informational `Not compared` row. The scope is applied before the 20-file cap. The YAML writer quotes every scalar a YAML 1.1 / 1.2 parser could misread (`no`, `on`, `y`, `~`, `1_000`, `0x1F`, `1e3`, `1:30`, dates), tested with a Psych round trip. The scoped unresolved count leaves out the other scope; one channel over the 28 KB page budget has its operations halved until it fits; a symlinked declared document is named. Documented limits: compound credential-shaped names the shared gate accepts, `a{x}b` and `${K:default}` addresses.
