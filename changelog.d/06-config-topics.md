- Add config-driven topics (9.0 T6, tag `config_topic`): a producer or consumer whose topic is read from configuration is recorded as a Spring-style placeholder `${KEY}` / `${KEY:default}` and resolved against the workspace's configuration files when the file is folded into the graph. Recognised reads: TypeScript / JavaScript `process.env.X`, `process.env['X']`, `<config>.get('X')` / `getOrThrow('X')` (also through local and module constants and `?? 'default'`), Go `os.Getenv("X")` and `viper.GetString("a.b")`, Python `os.environ["X"]`, `os.environ.get("X", "d")`, `os.getenv("X")`, and Java `@Value("${a.b}")` fields passed to `kafkaTemplate.send` (a `@KafkaListener(topics = "${a.b}")` was already recorded as the placeholder text). Values come from Spring `application*.yml` / `.properties`, the `.env.example` / `.sample` / `.template` / `.dist` dotenv templates, compose `environment:` and Kubernetes `env:` lists. HTTP routes never read these placeholders.
- Resolution never invents a name. One value is `exact`; two files that disagree (profiles), a `.env.example` / multi-document-yaml value or a bare `:default` give `heuristic` links and register every candidate (a deployed value always wins over a template one); a placeholder no file resolves, a cycle, or a chain deeper than 8 hops stays a visible `${KEY}` topic (`heuristic`), counted in `IndexHealth::config_topics_unresolved`. Go and Python no longer record the env KEY (`os.Getenv("KAFKA_TOPIC")`) as if it were the topic.
- A configuration edit re-resolves the topics of unchanged source files: the watcher re-folds every file holding a placeholder when a yaml / properties / dotenv file changes (that reload takes the full reconcile). The result equals a cold rebuild.
- Secrets (commandment 5): a real dotenv file (`.env`, `.env.local`, `production.env`, `.env.distributor`, ...) is never read; the only carve-out of the default `**/.env*` exclusion is the four exact template names (`ExcludeMatcher`, default pattern only). An entry is kept only when its value is topic-shaped (no scheme, no `@`, no token-looking run) and its key is not a credential, DSN, URL, URI, password or secret name. Resolution is bounded (256 steps, 8 candidates, checked while expanding, memoized per topic). Caps and failures are counted in `IndexHealth` (`files_config_capped` at 2,048 entries per file, `config_entries_dropped` at 50,000 per workspace, `files_config_parse_failed`, `files_config_lossy`) and `doctor` warns; a profile file next to a yaml that did not parse is weak; a non-UTF-8 config file keeps its valid lines. Java `@Value` fields are scoped to their class.
- Parse cache `SCHEMA_VERSION` 17 -> 18: the record of a TypeScript, Go, Python or Java file can now hold a placeholder topic; existing caches are re-parsed once.
- Existing tests that pinned "an env read records nothing" now pin the placeholder (`js_messaging.rs`, the Python variable-topic test). `docs/parser-support.md` section 3.5 lists what is and is not resolved.
