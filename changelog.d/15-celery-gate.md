- Python Celery detection is gated on the file's imports and module-level names (9.0 T15). A decorator is a Celery consumer, and `.delay()` / `.apply_async()` (also behind `.s()`, `.si()`, `.signature()`) a producer, only on a Celery origin: `@shared_task` / `@task` imported from a celery module; `@x.task` / `@x.shared_task` where `x` holds the token `celery`, is assigned from `Celery(...)` / `make_celery(...)` / `create_celery(...)`, or is imported from a `celery` module, under a `celery` name or from a module with a `tasks` segment; a producer on a name bound by a `from` import (any module outside a small deny list: invoke, fabric, locust, prefect, huey, dramatiq, arq, rq, luigi, multiprocessing, gevent) or on a consumer of the same file. Words match tokens, not substrings (`mycelery_utils`, `subtasks`, `from invoke import tasks` are no Celery). A Locust `@task`, a local decorator named `task`, a `task` of another library and a file that merely imports `celery` next to `@locust.task` are no consumers, no queue nodes and no events. On otel-demo (12 rows) and bank-of-anthos (9 rows) all 21 Locust consumers are gone; online-boutique and the 13 golden `*.expected.yaml` corpora (305 tp / 2 fp / 13 fn, chains 34/38) are unchanged.
- Gain: the base never read `@shared_task` consumers or aliases such as `@st`, `@app.shared_task`, nor `x.s(2).delay()` (it emitted a producer named `s(2)`); a synthetic 22-site probe goes from 9/12 consumers and 9/10 producers with 8 false rows to 12/12, 10/10 and 0.
- Known false negatives (documented in `docs/parser-support.md` 2.4): `@app.task` where `app` is imported from a module whose path holds neither `celery` nor a `tasks` segment; `from celery import *`; a `.delay()` on a variable, parameter or `self.x`. `send_task()` was never read. Remaining false positive: `.delay()` on a name imported from another library.
