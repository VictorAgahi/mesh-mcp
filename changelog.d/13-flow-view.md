- `visualize_mesh` gains an event flow view (9.0 T13): `event` (a topic name or its broker-qualified key, matched like `trace_flow`) draws a Mermaid `flowchart TD` centred on that event, producers upstream (`hops_up`, default 2) and consumers downstream (`hops_down`, default 2, both 1-5). It runs the chain engine of `trace_flow` (a reverse and a forward trace), no second graph walk. Options: `direction` (both / upstream / downstream), `detail` (every call as a node instead of an arrow label such as `3 calls`), `limit` (node cap, default 60, max 200), `fan_out` (1-50), `include_tests`. Every node carries its `path:line`; arrows are solid (exact), dashed (heuristic) or dashed red `?` (ambiguous); every event node is broker-qualified (`kafka:orders`, `?:` when the broker is not statically known) and two brokers' channels of one name never join.
- Nothing is cut silently: a continuation not statically resolved is a dashed hexagon (`not statically resolved: no consumer found`), a placeholder or wildcard topic is drawn with the same style, a bound (depth, fan-out, call depth, hop limit) is an orange stub plus a **Depth limit reached** / **Fan-out cap** note, the node cap says `**N nodes not shown (cap L)**, use hops/limit/scope` and marks each node that lost neighbours, cycles and joins are drawn once with a dashed thick border. The output stays under 48 KB (the node cap halves until it fits), deterministic.
- Labels are Mermaid-escaped (numeric entities for quotes, brackets, parentheses, braces, pipes, semicolons, `#`, `&`, `<`, `>`, backticks and non-ASCII), cut at 40 characters in the diagram, whole in the table below it; names go through `name_is_printable` (credential-shaped names print as `[REDACTED_SECRET: USE_ENV_OR_LOCAL_FALLBACK]`, also in the echo of `event`). `format: json|html` or `service` together with `event` is refused (`-32602`). New fixture `examples/eda/flow-view` (a request -> issue -> ledger cycle in directories named `(billing)`, `[id]`, `été`, `ledger;v2`, a runtime-built topic, a route with braces, a consumer that publishes nothing).
- No extraction change: `SCHEMA_VERSION` unchanged, no tool added, the chain engine (`contracts::flow`) untouched (read-only helpers `ContractGraph::flow_centres` / `hub_label_broker` in a new `contracts::flow_view`).
