- Add `event_anomalies`, the ninth MCP tool (9.0 T9): a workspace event anomaly report in one call. Classes: topics published but never consumed, topics consumed but never published, cycles (event chains that loop back: the strongly connected topics, the shortest loop as witness, each hop with its consumer and producer `path:line`), abnormal fan-out (a topic with 6 or more consumer sites, a file publishing onto 6 or more topics: the constants `ANOMALY_FAN_OUT_CONSUMERS` / `ANOMALY_FAN_OUT_TOPICS`) and topics whose only consumers are in test files. A separate **unresolved** class (not an anomaly) holds the one-sided topics whose other end may exist, with the reason: a `${KEY}` placeholder no configuration resolved, a wildcard subscription, a dead-letter / retry channel. "No producer" always means none statically resolved in the indexed roots; the answer says so and counts the files the index did not read.
- Surface: a new tool, not a flag on `trace_flow` or `analyze_impact`: the answer is a set of rows over the whole workspace (no target, no hop structure), which neither tool's schema can carry, and it keeps their descriptions and negative constraints intact. Arguments: `scope` (resolved through `ValidatedScope`; keeps the rows with a site under it, the analysis still reads every root), `classes`, `limit` (default 25 per class, max 100), `offset`. Tool count 8 -> 9: `CLAUDE.md`, `README.md`, `SETUP.md`, `docs/mcp-tools.md` (schema drift check), `docs/governance-rsah.md`, `docs/architecture/` (01, 04, 07, README), the server instructions and the `init` guidance are updated; no stale tool count is left in the docs.
- Rows are per broker (a name used on two known brokers is two rows, never joined); a site of unknown broker joins every channel of its name and makes the row `heuristic`. Test files are not production sites. Cycles rest on resolved call paths only (the same-file guess of `trace_flow` is counted in the footer, never a reason to report a loop). Placeholder topics are never part of a cycle or a fan-out. Topic names are checked again before printing (`constant_is_a_name`, the placeholder-default mask): a token-shaped name prints as `[REDACTED_SECRET: USE_ENV_OR_LOCAL_FALLBACK]`.
- Implementation: `contracts::anomalies` (analysis; iterative Tarjan with visited sets, BFS witness, bounded at 20,000 consumer sites), `ContractGraph::topic_hops` in `contracts::flow` (one topic -> topic hop per consumer call walk, reusing the chain engine), `mesh-parsers::anomalies` (Markdown, payload held under about 40 KB per page), `tools::event_anomalies`.
- Tests: hand-annotated truth in `tests/golden/events/anomalies.report.yaml` over `examples/unresolved-flow`, `examples/eda/multi-broker`, `examples/eda/nestjs-monolith-bus` and the new fixture `examples/eda/anomalies` (one case of every class and its decoys); exact set equality per class plus a `must_not_flag` list. Byte-identical over runs and over a cold and a warm index cache; 380 KB file with thousands of topics; a ring of 3,000 topics and a 200,000-node chain on a 2 MB stack; credential canaries built at runtime. Known false positive, pinned in the golden file: a producer whose topic is built at runtime (`user:deletion:success`) reads as "consumed, never published".
- Known limit, not changed here: a Python `@task` decorator is read as a Celery consumer whatever the framework, so a Locust load test (`otel-demo`, `bank-of-anthos`) shows its tasks as "consumed, never published".
- No extraction change, no parse cache change (`SCHEMA_VERSION` unchanged).
